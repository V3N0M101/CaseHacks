# ReturnProof

A single-page marketing site with a server-side pilot request form. The static site lives in `public/` and has no build step.

## Deploy to Vercel

1. Import `V3N0M101/CaseHacks` into Vercel and select `main` as the production branch. Use the repository root, the **Other** framework preset and no build command. The checked-in `vercel.json` sets the output directory to `public`.
2. Create a Neon Postgres database or connect one through the Vercel Marketplace. In the Neon SQL Editor, run [schema.postgres.sql](schema.postgres.sql) against the database used by the site.
3. Set `DATABASE_URL` to the Neon connection string in the Vercel project’s environment settings. Set it for Production and redeploy if the initial deployment preceded the change. To test form submissions in Preview, use a separate Neon branch or database and apply the schema there too.
4. Submit a test request on the deployed site, confirm the row in Neon, and delete the test row. See the lead query below. A team member should check for new requests and follow up at the submitted work email.

## Deploy to Cloudflare Pages

From the repository root, use Node.js 22 or later and run:

```sh
npx wrangler login
npx wrangler d1 create returnproof-leads
npx wrangler d1 execute returnproof-leads --remote --file=schema.sql
npx wrangler pages project create returnproof --production-branch main
```

In the Cloudflare dashboard, open **Workers & Pages → returnproof → Settings → Bindings**. Add a D1 binding named `PILOT_DB` and select `returnproof-leads` for production. If you use preview deployments, bind a separate initialized D1 database for previews.

Deploy from the repository root so Wrangler bundles `functions/` alongside the static assets:

```sh
npx wrangler pages deploy public --project-name returnproof --branch main
```

Submit a test request on the deployed site. Confirm it appears in the D1 console, then delete that test row. The form stores leads and shows an on-page confirmation. A team member should check the database and follow up at the submitted work email.

## Run Cloudflare Pages locally

```sh
npx wrangler d1 execute PILOT_DB --local --file=schema.sql --config wrangler.local.jsonc
npx wrangler pages dev public --d1 PILOT_DB=00000000-0000-4000-8000-000000000001
```

Open the address printed by Wrangler.

## Review pilot requests

Run this query in the Neon SQL Editor or D1 console:

```sql
SELECT id, name, work_email, store_url, monthly_returns, created_at
FROM pilot_requests
ORDER BY id DESC
LIMIT 50;
```


## Deploy the merchant inspection portal to Cloudflare Workers

The portal is in [demo/](demo/). It is separate from the marketing site and pilot form. Buyers capture the item and label in your phone app or mobile return flow. That flow's backend submits the images. Merchants sign in to review the resulting findings and accept or reject the return. The portal does not trigger a Shopify refund.

1. Run `npx wrangler login`. If needed, create the database with `npx wrangler d1 create returnproof-inspections` and copy its ID into [demo/wrangler.jsonc](demo/wrangler.jsonc) under `INSPECTIONS_DB`.
2. In Cloudflare Zero Trust → **Access → Applications**, add a self-hosted application for the merchant portal hostname at `/review` and `/review/*`. Allow only merchant reviewers. Set `ACCESS_TEAM_DOMAIN` to your team's `<team>.cloudflareaccess.com` hostname without a scheme, and set `ACCESS_AUDIENCE` to the Access application AUD tag. The Worker also verifies the Access token.
3. Install dependencies, apply the database migrations, and configure and deploy the Worker:

   ```sh
   npm ci
   cd demo
   npx wrangler d1 migrations apply INSPECTIONS_DB --remote
   npx wrangler secret put OPENAI_API_KEY
   npx wrangler secret put BUYER_INTAKE_TOKEN
   npx wrangler deploy
   ```

   If you created the original `inspections` table by pasting the SQL in the dashboard, apply [0002_buyer_reference.sql](demo/migrations/0002_buyer_reference.sql) once to that database. The automatic migration command assumes the original migration was applied through Wrangler. Use a random intake token of at least 32 URL-safe characters, for example one generated by `openssl rand -hex 32`. Configure the same token in your buyer backend's secret store. Keep it out of the phone app, browser code, and Git.

4. In the Worker's **Settings → Domains & Routes**, assign the hostname used for Cloudflare Access. Open that hostname as a merchant. The root redirects to the protected review queue.

### Connect the buyer's capture backend

Authenticate the buyer and verify their return in your existing flow. Resolve the expected SKU and catalog photo on the backend. Extract two usable JPEG frames of the whole item and two of the label from the phone capture. Send a server-to-server request:

```http
POST /api/inspect
Authorization: Bearer <private BUYER_INTAKE_TOKEN>
Content-Type: application/json
```

```json
{
  "buyerReference": "return-4821-capture-1",
  "sku": "RP-WK-044",
  "catalog": "<base64 JPEG>",
  "item": ["<base64 JPEG>", "<base64 JPEG>"],
  "label": ["<base64 JPEG>", "<base64 JPEG>"]
}
```

Use base64 without a data URL prefix. Each encoded image can be up to 500,000 characters. A new submission returns HTTP 201 with `reference` and `buyerReference`; a successful retry with the same buyer reference and SKU returns the original receipt with HTTP 200. Use a new buyer reference for a new capture. Never include buyer personal details in the reference. The buyer capture app and its backend are separate from this repo.

For a smoke test, send one authorized test submission, confirm its reference appears in `/review`, record a decision, and refresh to verify it persists. Confirm a signed-out request cannot read the queue. The Worker keeps findings and decisions for 30 days in D1. The Worker does not retain source images or video. The vision provider processes the submitted images under your account data controls.

For local D1 setup, run `npx wrangler d1 migrations apply INSPECTIONS_DB --local` from `demo/`, then start `npx wrangler dev`. Set local secrets in the untracked `demo/.dev.vars`. Authenticated review requires a valid Cloudflare Access application token.
